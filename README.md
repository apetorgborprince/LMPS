# LMPS — Learner Plan Management System

LMPS is a Flask application backed by the **LMPS Supabase project**.

## Target workflow
ADMIN handles system administration. The operational workflow is:

**TEACHER → HEADMASTER → SISO**

The active roles are ADMIN, TEACHER, HEADMASTER and SISO.

## Architecture
Flask UI → Blueprint routes → Supabase repositories → Supabase Auth + PostgreSQL RLS + Supabase Storage.

## Supabase project
- Project: LMPS
- Ref: ortguwsycwtxhdatmxmt
- Region: eu-central-1
- PostgreSQL: 17

## Local setup
1. Create a Python virtual environment.
2. Run `pip install -r requirements.txt`.
3. Copy `.env.example` to `.env` and configure the Supabase keys and Flask secret.
4. Run `python wsgi.py`.

The service-role key is server-only.

## Security
- Supabase Auth owns passwords.
- Supabase tokens are kept in a private server-side token store; the browser cookie contains only an opaque session identifier.
- PostgreSQL RLS is the authorization boundary.
- Learner-plan transitions are enforced by database triggers.
- Notifications are generated by database triggers.
- Audit events are stored in `public.audit_logs`.
- SISO access is scoped to assigned schools and approved learner plans.
- CSRF protection is enabled.

## Application areas
- `/teacher`
- `/headmaster`
- `/siso`
- `/admin`
- `/notifications`

## Storage
Learner-plan documents use the private Supabase Storage bucket `learner-plan-attachments` and `public.plan_attachments` metadata.

## Vercel deployment

The repository includes a Vercel Python entrypoint at `api/index.py` and a `vercel.json` configuration.

For the current LMPS deployment:
1. Import repository `apetorgborprince/LMPS`.
2. Select branch `db10-supabase-migration`.
3. Keep the project root at the repository root.
4. Add these Vercel Environment Variables:
   - `SECRET_KEY`
   - `SUPABASE_URL`
   - `SUPABASE_PUBLISHABLE_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `SESSION_TOKEN_DIR=/tmp/lmps_sessions`
   - `SESSION_COOKIE_SECURE=true`
   - `SESSION_LIFETIME_MINUTES=60`
   - `MAX_UPLOAD_SIZE_MB=10`
5. Do not commit or expose the Supabase service-role key.
6. Redeploy after saving the variables.

### Vercel session note

LMPS currently uses a server-side filesystem token store to keep the browser cookie opaque. Vercel serverless storage is ephemeral, so this is suitable for initial deployment/testing but should be replaced with a persistent session store before relying on multi-instance production traffic.

## Deployment checklist
Set a strong secret, use HTTPS, make SESSION_TOKEN_DIR private and persistent, configure Supabase Auth redirects/email, create the initial ADMIN, configure school/year/term, create staff accounts, create teacher assignments, assign SISO schools, and exercise one complete teacher → Headmaster → SISO workflow.
